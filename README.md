# Movie-Recommendation-system
原始索引不起决定性作用，主要是位置索引定位返回电影名称
1.读取数据，根据电影种类创建标签并特征向量化返回成矩阵。
2.通过计算cosine_similarity得出test_movie与其他movies的相似度数组。对其中每个元素创建位置索引（注意不是原始索引/行号），enumerate把原始索引映射成(0，1，2，...)，对相似度进行降序排序，切片。
3.输出result时排除test_movie。针对位置编号返回电影名称
4.最后输出相似的电影

缺点：
1.无论分数高低，都返回相似的电影，但不满足观众的需求。
2.不能预测其他观众想看的类型的电影，比如看惯了动作片想看文艺片。

#update26.4.27
此次更新基于协同过滤的推荐，更加人性化地推荐用户可能感兴趣的电影。
思路：
1.对数据进行矩阵化并筛选出n部有评分的电影和m个用户。
2.计算相似度，并再次表格化便于索引查找电影信息
3.函数思路，确定某一位用户，根据相似度降序查找前十名最相似的用户。查找用户所有评过分的电影以及该用户自身评过分的电影，做差集。
将剩余所有电影评分取平均降序取前五部分数最高的电影作为推荐。

缺点：
1.余弦相似度只看角度不看模和相对位置，假如有托和恶意低分，会被判断为喜好相同。（改进方法：用Pearson相关系数 i.e.先去中心化再算cos）
2.算例瓶颈，目前是基于用户的协同过滤，但用户增长无上限，相似度矩阵维数过高内存过大。（改进方法：用基于物品的协同过滤，计算电影之间的相似度）
3.数据稀疏导致的推荐盲区，假如有用户偶尔看/看得少/看冷门电影，在thresh步骤会被筛掉（改进方法：对此类用户使用混合推荐，i.e.对他们使用不需要用户评分的内容推荐）
4.马太效应，高评电影会占主流，冷门片没有宣发资源（改进方法：降低热门电影的权重）
